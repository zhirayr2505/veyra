# VEYRA — REDESIGN IMPLEMENTATION SPECIFICATION v2.0
**Дата:** 2026-10-09  
**Статус:** ТЗ к выполнению; **не** отчёт о внедрённом редизайне.  
**Основа:** существующий проект \`zhirayr2505/veyra\`, \`docs/VISUAL_POLISH_PLAN.md\`, \`docs/REQUIREMENTS.md\`, текущий код React/Vite, работающие Telegram Mini App и боты.

## 0. Задача
**Полностью визуально отполировать VEYRA**, чтобы Welcome, регистрация, пять главных разделов, чаты, оба профиля, Match, Premium, Boost, настройки, поддержка, рефералы и вспомогательные состояния воспринимались как один премиальный продукт. Избавиться от разнородных иконок, дешёвых эффектов, старых случайных CSS-решений, дефектов адаптивности и видимых технических символов вроде \`}\`.

**Важно:** сначала целостность и надёжность, потом анимации. Не менять бизнес-функции, схему БД, цены, лимиты, переписки и модерацию. Не заменять утверждённый логотип, не создавать пользователей и фейковые показатели, не включать подарки или новые способы оплаты.

**Итог:** готовое мобильное приложение с корректной графикой и одинаковым визуальным качеством всех экранов; ни одного placeholder без осмысленного визуального состояния и работающей навигации.

## 1. Характер бренда — Midnight Atelier 2.0
VEYRA — не игра и не киберпанк. Эстетика: **luxury editorial / midnight romance / soft dimensional materials**. Главный объект внимания — фотографии и имена людей. Свет и декор помогают найти главное действие, а не заполняют каждый сантиметр.

Минимальная touch target 44×44, у основных кнопок 48–52 px. Базовая ширина приложения до 560 px; полноэкранный профиль подчинить той же оси. Safe areas сверху и снизу через \`env(safe-area-inset-*)\` и Telegram viewport.

**Материалы:** основной слой матовый; glass только для нижней навигации, верхнего контрола на фото и overlay. Тени мягкие, почти чёрные. Блики — тонкие косые полосы, едва заметные, только на featured-сегментах и Premium. Без вечного «дыхания» десятков элементов.

## 2. Дизайн-система и архитектура CSS
1. Создать единый \`web/design-tokens.css\` с токенами цвета, шрифта, spacing, радиусов, motion и z-index.
2. Создать/выделить примитивы \`VeyraButton\`, \`VeyraIconButton\`, \`VeyraPanel\`, \`VeyraChip\`, \`VeyraInput\`, \`VeyraSheet\`, \`VeyraSkeleton\`, \`VeyraEmptyState\`, \`VeyraToast\`. Мигрировать существующие компоненты постепенно, не переписывая бизнес-логику.
3. Свести стиль из \`style.css\`, \`redesign.css\`, \`premium-ui.css\`, \`registration.css\`, \`experience.css\` и профильных CSS к единому источнику токенов. Устранить конфликтующие дубли, учитывая порядок импортов и специфичность селекторов. Не добавлять ещё один гигантский override-файл.
4. Только у кнопок и интерактивных поверхностей — active/focus/disabled/busy-состояния; не менять native semantics и клавиатурную доступность.
5. Скелетоны соответствуют размерам фактических карточек, чтобы контент не прыгал при загрузке. Для пусто/ошибка/нет сети есть иллюстрация, ясный текст и реальное действие.

## 3. Единые иконки и фирменная графика
- Источник правды: компонент \`VeyraIcon\` поверх существующего \`UIIcon\` и \`/graphics/icons/veyra-icons.sprite.svg\`. Там, где в спрайте нет нужного glyph, создать SVG в сетке 24×24 с \`strokeWidth=1.75\`, закруглёнными концами/соединениями и одинаковым optical weight. Размеры: 16 secondary, 20 list/inline, 22 action, 24 navigation. Активность обозначается цветом/фоном/скромной заливкой, а не иным случайным набором.
- Сначала составить карту \`glyph → где используется → есть ли в sprite → нужно ли дорисовать\`. При миграции \`main.jsx\`, \`registration.jsx\`, \`chat.jsx\`, \`chat-media.jsx\`, \`member-profile.jsx\`, \`profile.jsx\`, \`account-pages.jsx\` избегать нескольких разных пиктограмм для одного действия.
- Сохранить **утверждённый** логотип и существующие иллюстрации из \`public/graphics/illustrations\`: \`discover-cards\`, \`today-coffee\`, \`chat-bubbles\`, \`match-hearts\`, \`premium-crown\`, \`referral-gift\`, \`review-shield\`, \`boost-rocket\`.
- Новые графические элементы создавать только для реально недостающих состояний и в одном языке: матовые 2.5D формы, нежная окантовка rose/orchid/ice, мягкий отражённый свет, аккуратная глубина, фон transparent. Не применять случайные stock/photo-ассеты, не использовать лица реальных пользователей для декоративных сцен и не придумывать изображения «пользователей».
- Сохранять источник/лицензию ассетов в \`public/graphics/provenance.json\` и связанных документах. Использовать готовые SVG/WebP, оптимизированные для телефона, а не крупные PNG там, где они не нужны.
- Подарки: только фирменная заглушка «Скоро»; не создавать действующие витрины, списания, анимированные платные подарки до отдельного утверждения.

## 4. Поэкранные макеты и критерии

### 4.1 Welcome / загрузка / авторизация
**Композиция:** утверждённый VEYRA бренд вверху; hero фото с аккуратным тёмным градиентом, короткий крупный headline, ясная кнопка Telegram. Внизу — читаемый 18+ и legal. Лоадер — символ V со спокойным shimmer/breathe один раз, без тяжёлых прелоадеров.
**Проверить:** при узкой высоте CTA остаётся доступным, нет наложений на статус-бар Telegram, fallback при задержке картинки не оставляет пустой белый прямоугольник.

### 4.2 Регистрация (5 существующих шагов)
**Шапка:** заголовок, один поясняющий абзац, сегментированный прогресс «1/5», все отступы общие. **Поля:** одинаковые label/placeholder/error; активная рамка orchid без агрессивного свечения. Выбор пола, интересов и предпочтений — одинаковые chips/cards без случайных emoji-шрифтов; даты и возраст — удобные нативные input. Геопоиск: ясный loading/список городов/ошибка. Фото: сетка с главной карточкой и прозрачной нумерацией 1–6, reorder/замена/удаление без потери affordance. Согласие 18+ и модерация — явно видимые состояния.
**Не менять:** возрастную проверку, пятишаговую схему, требования к фото и приватный draft. **Проверить:** ввод с клавиатурой, ошибки, прерванную регистрацию, 320px.

### 4.3 Лента (Feed)
Фото занимает главное пространство, изображение без crop лиц. Верхние фото-индикаторы 3px, небольшие иконки управления. Имя/возраст — главный контрастный текст; город, цель, 2–4 интереса — вторичный уровень; остальные данные открываются в полном профиле, а не перекрывают фото. На имя и «Открыть профиль» можно нажать; не конфликтует со свайпом. Четыре основные реакции имеют одинаковую логику обводки/активности, но понятные раздельные цвета. Отмена Premium не выглядит как основная реакция.
**Проверить:** 320×568, длинные имена, биография, 1/6 фото, тап/свайп, нулевые рекомендации и лимит.

### 4.4 Сегодня (Today)
Header «Сегодня», короткое вдохновляющее описание и фирменная иллюстрация. Блок «Я свободен» — компактная качественная панель с временем (сейчас/вечером/после 21), выбором действия и переключателем. Список людей — единые карточки, близкие Feed, но более информативные; кнопки «Профиль»/«Нравится» не перекрывают текст. Идеи встреч — собственные иконки тематики, **без выдуманных ресторанов и событий**.
**Проверить:** отсутствие людей, на паузе, loading, актуальность надписи времени.

### 4.5 Лайки и история
Премиальная сетка без ложного показа скрытых фотографий. Incoming count, открытые профили Premium, outgoing, Super Likes и Match history имеют одни и те же сетку, миниатюры и подписи. Пусто = иллюстрация + понятная кнопка в ленту. Paywall приглашает, а не пугает. Открытие карточки ведёт в **полноценный** профиль.
**Проверить:** Free/Premium, долгие имена, пустую историю, переход в чат через matched profile.

### 4.6 Экран взаимной симпатии
Центр: две реальные фотографии в одинаковых красивых рамках, брендовый визуал \`match-hearts\`, короткий заголовок, ненавязчивый сияющий ореол. Основная кнопка — «Написать» / переход в чат, вторая — «Посмотреть профиль», третья — «Продолжить поиск». Анимация: мягкая сборка фотографий + одиночное световое сердечко, не бесконечное конфетти.
**Проверить:** навигацию и перекрытие модалок, возвращение с профиля обратно, 320px.

### 4.7 Чаты — список
Ясная типографика: аватар, имя, статус/последнее сообщение, время, непрочитанное. Разделители тонкие, hit area на всю строку; единая обработка «голосовое», «фото», «стикер», «печатает» при наличии реальных данных. Поиск и пустое состояние оформлены фирменно. Нет декоративных fake online badges.
**Проверить:** длинные сообщения, ноль чатов, поиск без результатов, прочитано/непрочитано, 320px.

### 4.8 Переписка — самое высокое внимание к деталям
Header: фото, имя и меню — единая сетка. Тап на имя ведёт в полный профиль; «Назад» возвращает без потери черновика. Пузырьки: входящие/исходящие разнятся материалом и положением, а не чрезмерным неоном; timestamps и read ticks остаются видимыми. Поле ввода, send, emoji, attach, voice и sticker используют единый набор иконок. Аудио waveform, speed, seek, фото-превью, галерея, long-press, reply, edit/delete/report — визуально согласованы. Recording bar чётко различает request/record/pause/ready/error.
**Проверить:** клавиатуру и safe area, длинные сообщения, несколько картинок, 10-минутный лимит аудио, неотправленные сообщения и retry без дубликатов.

### 4.9 Полный профиль другого пользователя
Полноэкранный экран с шапкой VEYRA + «Назад», большая фотогалерея, имя/возраст/город, цель, о себе, интересы, отметка модерации без заявления о верификации личности. Match => sticky кнопка «Перейти в чат»; до match => лайк, Super Like и действующие ограничения. Жалоба/скрытие — вторичные безопасные действия. Совпадение цветов, радиусов, ширины и safe area с \`My Profile\`.
**Проверить:** переходы из Feed, Today, Likes, Chats и Match; ошибки прав доступа, скрытые/заблокированные профили; возвращение на прежний экран.

### 4.10 Мой профиль
Крупная обложка, галерея, Edit как очевидное действие; «Обо мне», общие панели интересов/статистики, состояние проверки/паузы. Premium-панель — яркая, но только одна. Настройки/приглашения/поддержка — одинаковые row-компоненты. Не вводить данные, которых не существует.
**Проверить:** 1–6 фото, длительную биографию, паузу, предварительную модерацию и повторное редактирование.

### 4.11 Premium / Boost / Stars
Иерархия преимуществ с утверждённой графикой \`premium-crown\` и \`boost-rocket\`, карточки тарифов с настоящими значениями каталога, явное выбранное состояние и одна CTA. Premium — роскошный точечный свет, а не 12 glow-рамок. Refund/pending/disabled отражаются честно; никаких гарантированных просмотров Boost.
**Проверить:** Live/disabled payments, переключение тарифов, высоту на маленьком экране и корректное подтверждение.

### 4.12 Settings / Support / Referrals / модули админки
Фирменная панель, минимальный визуальный шум. Все формы, тумблеры, списки, ошибки, danger actions выглядят родственными. Реферальная карточка с красивым изображением и копированием; тикеты и FAQ — читаемые; админка сохраняет плотность данных, высокий контраст, правильные role boundaries и экспорт. Не жертвовать функциями ради красоты.
**Проверить:** focus/keyboard, опасные подтверждения, RU/EN, длинные тексты, 320px и 560px.

## 5. Матрица анимаций
| Элемент | Анимация | Длительность | Ограничение |
| --- | --- | --- | --- |
| Обычное нажатие | \`scale(.98)\` + цвет | 120–160ms | Без сдвига layout |
| Переход раздела | fade + translateY(8px) | 180–240ms | Сохранение scroll position, где нужно |
| Открытие Sheet | translateY(16px) + opacity | 260–320ms | Фокус и Escape/Back |
| Профиль человека | плавный overlay fade | 220–260ms | Без потери черновика/состояния |
| Match | фото + одиночный glow | 500–850ms | Только при реальном мэтче |
| Premium-блик | sweep highlight | 800–1200ms | Не чаще раза в 6–10 секунд |
| Skeleton | shimmer | 1.2–1.6s | \`prefers-reduced-motion\` |
| Лайк / Super Like | короткий pulse | 220–350ms | Не имитировать ложный мэтч |
| Состояние отправки | check/tick fade | 150–220ms | Реальный подтверждённый статус |
| Ошибка | короткий fade / shake ≤3px | ≤220ms | Не прятать текст ошибки |

Использовать преимущественно \`opacity\` и \`transform\`. Не держать активные анимации на скрытых страницах. При \`prefers-reduced-motion: reduce\` убрать декоративные циклы, оставить смысловые переходы минимальной длительности.

## 6. Обязательная техническая зачистка UI
- Прицельно воспроизвести и устранить видимый символ \`}\`: установить экран/DOM node/component/условие появления, исправить исходный JSX или локализацию; не скрывать с \`display:none\` без понимания причины.
- Найти пустые/битые изображения, неправильные пути SVG-спрайта, broken crop, горизонтальный scroll, переполнение карточек, разрывы длинных имен/переносы, уход кнопок под navigation.
- Проверить состояния offline, 401, 403, 404, 500, loading, нет профилей, нет чатов, paused, pending review.
- Поддерживать реальный RU/EN и существующие даты/денежные значения; не заменять пользовательский текст иллюстрациями.
- Исключить новый источник «фальшивых» данных: никакие статусы активности, лайки, рейтинги и количества не рисовать без API.

## 7. Микрофон — отдельный UX-дефект в этом релизе
Текущий \`useVoiceRecording\` в \`web/chat-media.jsx\` вызывает \`getUserMedia\` при каждом начале записи и останавливает tracks после записи. Это следует изучить и по возможности сократить ненужные запросы, но WebView может повторять системное окно независимо от JS. Нельзя обещать, что системное разрешение запрашивается строго один раз.

**Требования:** различать permission not asked / granted / denied / unsupported (где Web API позволяет), запрашивать микрофон только после нажатия пользователя, гарантировать отсутствие двойного одновременного recorder, корректно останавливать запись и освобождать микрофон после завершения, не удерживать скрытый stream ради предотвращения permission prompt, показывать конкретную инструкцию для настроек Telegram/Android в случае повторного системного запроса. После refusal не зацикливать диалог. Не ломать отправку, паузу, отмену, waveform, retry.

**Ручные проверки:** первый запрос → разрешить → 2-я/3-я запись → отмена → пауза → отправка → закрытие/повторный вход → отказ → разрешение в системных настройках. Проверять физический Android Telegram и браузер отдельно; автотесты со stub-микрофоном не доказывают поведение Telegram.

**Этап 3 — admin + motion:** привести админку к общей палитре, анимации и пустые состояния; не ломать data tables.  
**Этап 4 — приёмка:** скриншоты 320×568, 390×844, 560×840; Telegram Android реальная проверка; \`npm run lint\`, \`npm run check\`, \`npm run secrets:check\`, один полный \`npm run test:browser\` после существенных изменений; итоговое сопоставление production revision через Render \`/healthz\` и \`/readyz\`.

**Экономия лимитов Work/CI:** не клонировать репозиторий заново, не переустанавливать Chromium между каждой мелкой правкой, не перезапускать полный e2e после одной замены цвета, не регенерировать существующие графические пакеты. Проверять точечно изменённый экран, полный набор — в конце этапа. Не создавать тестовых пользователей в production, не сбрасывать регистрации, не менять миграции/секреты.

## 9. Критерии готовности (Definition of Done)
1. Все пункты карты экранов визуально согласованы; никакие разнородные emoji/Lucide/brand-иконки не остались рядом случайно.
2. Нет воспроизводимого \`}\` и других случайных символов, нет сломанных изображений, критичных overflow/обрезаний.
3. Все изображения / графика имеют корректные fallback; новые ассеты включены в репозиторий и имеют происхождение.
4. Никакое базовое действие пользователя не потеряно: свайп, мэтч, чат, фото, аудио, платежи, пауза, модерация, настройка, отчёт, экспорт.
5. Все интерактивные зоны не меньше 44×44 px, видимый keyboard focus; поддержаны \`prefers-reduced-motion\` и Telegram safe area.
6. Страницы совпадают по сетке и материалам на 320/390/560px; text wrap и открытая клавиатура не скрывают главные действия.
7. Компоненты используют централизованные токены; количество дублей/каскадных override сокращено без потери рабочего поведения.
8. Голосовые корректно записываются, отправляются/отменяются; Android Telegram prompt поведение задокументировано честно, без скрытого захвата микрофона.
9. Отдельно подтверждены успешные автоматические проверки и фактическое развёртывание нужной Git SHA; green CI не означает live deployment.
10. Есть краткий финальный changelog: \`screen → изменения → ассеты → как проверено → ограничения\`.
