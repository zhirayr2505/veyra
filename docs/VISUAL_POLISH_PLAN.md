# VEYRA — Visual Audit & Premium Art Direction v1
Дата: 2026-10-09. Основа: текущая ветка main репозитория zhirayr2505/veyra. Это **аудит исходного кода**, не подтверждение визуального результата в Android Telegram. Никакие функции, оплаты, контент и база данных этим документом не меняются.

## Цель и границы

Сделать все существующие экраны VEYRA единым качественным продуктом: без разнородных иконок, случайных отступов, лишних символов, визуальных дефектов и перегруженного неона. Сохранить бренд, утверждённый оригинальный логотип, существующие API и бизнес-логику, пять разделов Feed / Today / Likes / Chats / Profile, компактную пятишаговую регистрацию и реальные ограничения Premium. Не добавлять необоснованные обещания, фиктивные лайки, фейковые места или новые платные механики. Подарки остаются Coming soon.

## I. Выводы по реальному коду (подтверждено)

1. Визуальные стили наслаиваются: `web/style.css`, `web/redesign.css`, `web/premium-ui.css`, `web/registration.css`, `web/experience.css`, `web/profile.css`, `web/member-profile.css`, `web/chat.css`, `web/chat-media.css` и стили админки. Корневые переменные, размеры `.topbar`, `.button`, `.card-info` и фон переопределяются в нескольких слоях. Это повышает риск регрессий и разницы между экранами. **Решение:** единые дизайн-токены, базовые примитивы и постепенно изолированные стили; никаких новых каскадов поверх каскадов.
2. Иконографика смешанная. `web/graphics.jsx` определяет фирменный `UIIcon` из SVG-спрайта, `web/main.jsx` использует смешанную замену `iconNames` для части Lucide-иконок; разделы `web/chat.jsx`, `web/registration.jsx`, `web/profile.jsx`, `web/account-pages.jsx`, `web/member-profile.jsx` импортируют Lucide напрямую. **Решение:** единый `VeyraIcon` с размерами, stroke и заменами; фирменные символы приоритетны, недостающие — в одной сетке 24×24 и с согласованными 1.75px линиями.
3. Иллюстрации уже существуют: `discover-cards`, `today-coffee`, `chat-bubbles`, `match-hearts`, `premium-crown`, `referral-gift`, `review-shield`, `boost-rocket`, а также фирменные фоны, placeholders, status SVG и оригинальный логотип в `public/graphics`. **Решение:** не делать новые дубликаты; инвентаризировать и создавать ассет только для отсутствующего состояния, сохраняя происхождение/лицензии.
4. `web/member-profile.jsx` — отдельная полноценная страница поверх приложения, но `web/member-profile.css` использует локальную палитру и ширину до 600px, тогда как основное приложение рассчитано на 560px. **Решение:** единый контейнер, токены, header, safe area, галерея, действия и обратная навигация.
5. В `web/chat-media.jsx` хук `useVoiceRecording` при каждом старте вызывает `navigator.mediaDevices.getUserMedia`, а `cleanup` останавливает дорожки после записи. Это может участвовать в повторных permission prompts. Но Android Telegram WebView/OS может решать, сохраняется ли доступ: **код не вправе обещать**, что системный запрос всегда появится ровно один раз.
6. Сообщённый пользователем артефакт `}` в интерфейсе пока **не локализован** по исходному коду. Нельзя утверждать, что он устранён, без скриншота конкретного экрана и/или проверки реального DOM. Проверить React-рендеринг, текстовые узлы, локализации, ошибки шаблонов и дополнительные контейнеры; закрепить исправление тестом.

## III. Art direction: Midnight Atelier 2.0

**Впечатление:** дорогой вечерний digital-fashion бренд, не neon-gaming, не шаблонный Tinder-клон. Лицо и фотографии — главный визуальный акцент. Графика дополняет, не спорит. Утверждённый VEYRA V/heart/star и словесное имя — без перерисовки, самостоятельной замены и изменения пропорций.

**Палитра (предлагаемые токены; сводить поэтапно, не массовой заменой):**
- Canvas `#090A12`, base surface `#12131D`, raised `#1B1928`, surface hover `#272033`.
- Text high `#F8F3FA`, text secondary `#B8A9C3`, subtle `#887C98`.
- Veyra rose `#F477B8`, orchid `#B67BE9`, ice `#88D3E6`, quiet gold `#E7C58C` (только покупка/премиум, не навигация).
- Delicate border `rgba(239,218,255,.10)`, interactive border `rgba(244,175,224,.22)`.
- Main CTA: `linear-gradient(112deg, #F477B8 0%, #DC59AB 45%, #A873DF 100%)`. Фоны — глубокие нейтральные, не сплошная розовая подсветка.

**Типографика:** один хорошо загруженный font stack, без скачка размеров: hero 30–34/1.1, section 22–26/1.2, card heading 18–21, body 14–15/1.5, secondary 12–13/1.5, eyebrow 10–11 с небольшим letterspacing. Кнопки не ниже 44px, главные CTA 48–52px. Не допускать текст ниже 11px там, где он несёт важную информацию.

**Сетка:** базовый шаг 4px, вертикальные интервалы 8 / 12 / 16 / 24 / 32, наружные отступы 16–20px. Радиусы: chip 10–14, button 15–18, surface 20–24, image hero 25–28. Единая ширина: учитывать исходный shell до 560px, а не создавать несовместимые standalone-maxWidth. Тени мягкие, размытые, почти чёрные; blur в основном для навигации/оверлеев, не в каждом элементе.

**Иконки:** один источник правды `VeyraIcon`: фирменный sprite для основных действий, недостающие SVG строго на сетке 24×24, stroke-linecap round/linejoin round, 1.75px; размеры 16 secondary, 20 list, 22 button, 24 tab, 28 decorative. Не смешивать толсто залитые и тонкие outline-иконки без семантической причины. Никаких emoji-иконок в навигации.

**Иллюстрации:** язык «soft dimensional editorial»: полуматовые формы, спокойный rose-violet-ice edge light, ограниченная глубина, качественные тени, цельный материал. Сначала переиспользовать имеющиеся 8 иллюстраций и оригинальные SVG-фоны. Новые SVG: только реально отсутствующие состояния, например «нет сети / нет мэтчей / разрешение на микрофон», если текущие assets визуально не подходят после проверки. Без лиц и персональных данных, без внешних недостоверных фотографий.

**Motion system:**
- Tap: 120–160ms, scale .98 + мягкий opacity.
- Navigation: 180–240ms opacity/translateY(6–10px).
- Sheet/modal: 260–320ms ease-out без «резинового» overshoot.
- Match: 500–850ms один акцент с `transform/opacity`, без бесконечного блестящего конфетти.
- Loading shimmer: 1.2–1.6s, один градиент; skeleton имеет ту же геометрию, что и загруженная карточка.
- Premium shine: не чаще 1 цикла в 6–10 секунд, только на главном оффере, не на каждом контуре.
- Соблюдать `prefers-reduced-motion`; не анимировать layout/height во время ввода; не держать постоянный `backdrop-filter` на десятках карточек.
- Тонкий тактильный отклик использовать через Telegram HapticFeedback там, где доступен.

## IV. Bug: повторный запрос микрофона — отдельная обязательная задача

**Подтверждённая реализация:** `web/chat-media.jsx` — `useVoiceRecording` при `start()` каждый раз вызывает `getUserMedia`; `cleanup()` прекращает stream tracks, а при ошибке показывает permission sheet. Проверка браузерных сценариев проводилась с синтетическим микрофоном, Android Telegram не проверялся.

**Корректный подход:** измерить `NotAllowedError` и `navigator.permissions.query({name:'microphone'})` только где поддерживается; не провоцировать повторное разрешение в промежуточных действиях, помнить состояние UI в рамках сессии; сохранять privacy и освобождать tracks после записи, **не держать живой микрофон скрытно ради обхода системных разрешений**. Если Android Telegram WebView повторно спрашивает после остановки stream, разбирать WebView/app/system settings и ограничения платформы. UI объяснения — короткие и ясные, без бесконечного цикла permission sheet. Системный prompt нельзя отключить JS-кодом вопреки WebView/OS.

**Критерии приёмки:** первый допуск, вторая запись в той же Mini App сессии, отказ, перезапуск приложения, уход в background, восстановление после отмены, запись/удаление/пауза/отправка; отдельно Android Telegram и браузер. Отсутствие потери записи, дубликатов, фонового захвата микрофона.

## V. План внедрения и ограничения

**Фаза P0 — без новой функциональности:**
1. Снять скриншоты реальных экранов на 320×568, 390×844, 560×840 и Android Telegram; поймать указанный пользователем видимый `}` с трассировкой до DOM/компонента.
2. Ввести `web/design-tokens.css` и эталонные примитивы: кнопки, icon buttons, input, chip, panel, sheet, skeleton, toast. Распутывать old CSS каскад **постепенно** с проверкой каждого экрана, не удалять пакет целиком.
3. Централизовать иконки в `VeyraIcon` и составить мини-инвентаризацию всех glyph/illustration assets с `used_in` и origin.
4. Точечно исправить странные символы, обрезания, сломанные states и микрофон (в тех пределах, что позволяет WebView). Добавить минимальные регрессионные тесты.

**Фаза P1 — полировка каждого экрана без изменения бизнес-логики:** Welcome → Onboarding → Feed → Today → Likes → Match → Chats/Conversation → Member Profile → My Profile → Premium/Boost → Referrals/Support/Settings → admin. Для каждого: интерактивность, skeleton, empty/error, адаптивность, размеры tap targets, RU/EN, slow device & reduced motion.

**Фаза P2 — финальная приёмка:** недорогие визуальные snapshot-скриншоты только изменённых экранов, проверка отсутствия `}`/сиротских символов, manual Android Telegram (включая permission/microphone), `npm run check`, `npm run secrets:check`, один полный browser CI перед отправкой финальной версии. Проверить Render `/healthz` ревизию и `/readyz` отдельно; один green CI не равен deployed production. Не запускать многократно browser-install, ffmpeg-install или пересборку одинаковых ассетов без причины.

**Граница:** этот документ — план, **не означает реализованный редизайн или исправленный микрофон**. Реализация начинается следующими самостоятельными коммитами, без сброса пользователей/платежей/БД и без удаления текущей рабочей логики.
